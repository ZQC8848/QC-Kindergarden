# story_review

给 `tools/story_pipeline` 生成的故事大纲打分、写批注、决定去向的**本地**网站。
只监听本机 `127.0.0.1`，不部署到 Vercel；它直接读写私有 submodule 里的
`ResearchAssets/story-candidates/`。

## 启动

```bash
python tools/story_review/server.py
```

正式模式：读写真实候选，点「生成下一轮」会调用真实模型（会先弹窗确认）。

```bash
python tools/story_review/server.py --dry-run
```

演练模式：先把候选目录复制到临时目录，模型换成假输出。怎么点都不会碰真实档案。

其他参数：`--port 4388`（默认端口）、`--no-open`（不自动打开浏览器）、`--candidates <目录>`（指定候选目录）。

只用 Python 标准库，不需要 npm。样式、字体、角色头像直接取自 `website/`
（`src/styles/global.css`、`public/fonts/`、角色海报），和网站是同一套视觉语言。

## 分数决定去向

| 分数 | 去向 | 批注 |
|---|---|---|
| 0–3 | 丢弃 | 必填：为什么丢。理由标签可以多选，只是辅助 |
| 4–7 | 候补 | 必填：好在哪、缺什么。下一轮生成时由原模型照批注重写 |
| 8–10 | 选中 | 可选。写了批注就是「选中 · 按意见重写」：提交后立刻交回原模型重写 |

分档定义在 `store.SCORE_BANDS`，终端的 `review.py --score` 用的是同一套。

## 两种重写

都交给**写这篇的同一个模型**，brief 是这篇原来那个位子的 brief，加上原大纲、你的分数和批注。

- **候补重写**：不马上发生。每次生成下一轮时，候补池里的故事全部带回来重写，出现在新一轮最上面，
  标「候补回炉 · 第 n 次」。同一条故事线最多重写 3 次（`store.MAX_REVISITS`），之后自动以
  `never_chosen` 退出。
- **按意见重写**：选中并写了批注，提交后立刻在后台重写。改写稿出现在原稿下面，标「按意见重写」，等你再批。

重写的字数上限可以单独调：候补卡片上有「下一轮重写上限」，选中带批注时表单里有「重写上限」。

重写稿不计入各模型的对比统计：同一个位子的四个模型收到的是逐字节相同的 brief，而重写的 brief 每篇都不一样。

## 字数上限

顶栏的「字数上限」是一个范围。生成时每个位子在范围内随机抽一个上限，同一位子的四个模型用同一个值，
所以对比仍然公平。抽到的值记在 `round.json` 的 `max_chars` 里，每篇候选也记了自己的 `max_chars`。

## 中文 / English

顶栏的 `EN` / `中文` 按钮切换界面语言，选择记在浏览器里。

- **固定的文字不走翻译**：界面、位子、场景名、角色名、丢弃理由、已发布故事的标题，都是写好的英文
  （场景、角色、故事标题取自网站的英文数据）。
- **动态内容走 Google 翻译**：模型写的标题、大纲、模型自述，以及你的批注——已经提交的，
  和正在输入框里写的。
- **输入框里的原文不会被替换。** 提交的永远是你打的原文，模型读到的也是原文；英文显示在输入框下面，
  停手约一秒后更新。
- **角色名固定译法**：中文名在送去翻译前会被保护起来，回来一律是网站用的英文名（陆姚 → Luyao，牧师 → Mushi），
  不会一会儿 "Lu Yao" 一会儿 "Pastor"。
- **key 不进页面**：翻译由本地服务器调用 Google（`translate.py`），浏览器只拿到译文。
- **缓存**：同一段文字只翻一次，结果存在 `ResearchAssets/.cache/story-review-translations.json`
  （私有 submodule 里，已 gitignore，不提交）。缓存里只有原文的哈希和译文。
- 注意：第一次翻译某段文字时，这段原文会发给 Google。

key 是 `GOOGLE_TRANSLATE_API_KEY`，放在 `ResearchAssets/config/story-pipeline.env`。查找顺序和模型的 key 一样：
环境变量 > 仓库根 `.env` > 私有配置。没有 key 或 Google 报错时，英文模式照样能用，只是故事内容保持中文，
顶栏会显示原因和「重试」。检查 key 是否可用：

```bash
python tools/story_review/translate.py "陆姚今天又炸了"
```

## 日间 / 夜间

顶栏 ☾ / ☀ 按钮切换。没选过时跟随系统设置，选过之后记在浏览器里。夜间主题是在网站的颜色 token 上覆盖一套深色值，
网站本身仍然只有日间主题。

## 创作偏好页面

顶栏的「评审 / 创作偏好」切到 taste 页面（地址 `#taste`）。它直接读 `.agents/skills/qc-taste/references/taste/`，只看不改：

- 五个标签：故事创作、图片生成、分镜头、视频生成，以及每个领域都要一起读的「共通」；
- 跟随顶栏的中英切换显示对应语言。这里是写好的双语文件，不走 Google 翻译；
- 标签上的圆点是中英同步状态：绿色已同步，黄色有一边落后，红色结构对不上（规则编号、标题或条目数不一致）；
- 文件改动后页面自动刷新。

同步由 `tools/taste_sync.py` 负责，规则见 qc-taste skill 的「Two languages」一节。

## 盲评

- 页面上不出现模型名：发给浏览器的候选数据去掉了 `model`、`taste_context`、`raw`，
  生成日志和重写报错里的模型名换成 `[model]`。
- 一轮全部裁完之前看不到各模型的表现；裁完后，轮次标题旁边会出现「揭晓模型表现」。
- 还有没裁的故事、或者还有按意见重写没跑完时，不能生成下一轮：候补池要等裁完才确定。

## 快捷键

`0`–`9` 打分，`=` 打 10 分，`n` 写批注，`j` / `k` 下一篇 / 上一篇，`Ctrl+Enter` 提交，`Esc` 离开输入框。

没提交的打分和批注存在浏览器本地，刷新页面不会丢。

## 改输出格式

模型的输出格式在 [`tools/story_pipeline/formats/default.json`](../story_pipeline/formats/default.json)，
不在代码里。加字段、改说明、换顺序，都只改这个文件：

- `show` 决定评审站把字段放在哪，`note` 会进卡片上的「模型自述」；`label` / `label_en` 是中英文标签；
- `Candidate` 没有的字段存进候选的 `extra`，照样显示，英文模式下也会翻译；
- 改了措辞或字段要升 `version`，每轮会记下格式的名字、版本和 sha256。只改标签不影响 brief，不用升。

想对比两种格式，就复制成 `formats/<新名字>.json`，再用 `run_round.py --format <新名字>` 跑。
