# Incident index — search by symptom

**Look up what you saw, not what it turned out to be.** When you start you know "the
face is frozen"; you do not yet know the device is returning a stale buffer.

Every entry here shares one property: **the symptom was far from the cause**, and the
evidence pointed somewhere else.

| What you see | What it actually was | Record |
|---|---|---|
| *(symptom, in the words you'd use before knowing the answer)* | *(one line)* | [link](YYYY-MM-DD-symptom.md) |

## Writing an entry

File name `YYYY-MM-DD-<symptom-phrase>.md`. **Name it after the symptom**, because the
cause is only known once you have finished.

Each entry needs:

- **Symptom** — what was visible, including what was absent. Zero errors is itself a clue.
- **Why it was hard** — which evidence pointed the wrong way
- **What was true** — with the measurement, not only the conclusion
- **Two-minute path next time** — the number to read, the command to run

Only write up faults that were expensive **because the evidence misled**. A typo that
cost four minutes is not a record.
